A saved measured mapping is used directly when RESUME / ON is pressed. Learn / validate measures both axes with bounded probes, returns to the starting encoder position, saves the mapping, and leaves tracking output OFF until you press RESUME / ON.

Before measuring either axis direction, learning runs three alternating forward/reverse sweeps in 0.02° encoder increments, up to 0.20°. It fits the repeatable transition from encoder-only travel to coherent pixel motion, rejects inconsistent/noisy trials, and takes up the measured backlash before calculating pixels per degree.

Vibration and lost-lock handling

Default: OFF. When enabled, this limits commanded travel relative to fresh encoder readings captured when Apply is clicked. It is not tied to an older session or telescope power state.

Vibration filtering smooths short excursions below the threshold; a persistent change is accepted after three frames. Return mode commands the last encoder position where the feature was visible, then stops there while the camera attempts reacquisition. It does not perform an unbounded sky scan.

Click the live image to lock a high-contrast point. KCF is the default because it keeps Raspberry Pi camera capture responsive; MOSSE is lighter and CSRT uses substantially more CPU. Changing tracker resets the current feature lock.

Default: 10 seconds. Late or missing encoder replies show a stale/unconfirmed notice, but the dashboard retains the warm Bridge connection and keeps polling. Only a closed socket or real network failure starts reconnection.

Reconnect Motor Link rebuilds only this dashboard's connection to a Bridge that is already healthy. Recover Bridge & Motor Link releases the dashboard client, stops the Bridge, allows the legacy Wi-Fi socket to close, refreshes the Pi's current LAN address, starts the Bridge, then requires fresh replies from both motor encoders. Use Recover after a Pi reboot, LAN-address change, stale Bridge connection or failed Reconnect. Neither action reboots the telescope Wi-Fi adapter.
